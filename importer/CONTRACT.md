# Aurora import contract v1

This is a one-way **2014 current-sheet snapshot**, not a ruleset library, level-up engine, synchronizer or Aurora exporter. A `.dnd5e` character and the XML content it references are the input. A versioned Aurora Core Reference (2014) pack is bundled automatically; see reference/NOTICE.md for its exact 91-definition scope and SRD 5.1 attribution. No complete commercial rulebook corpus is bundled. Files using 2024/unknown rules semantics must be explicitly identified and are blocked when their required calculations cannot be resolved.

The headless worker accepts one JSON request on stdin and writes one JSON result on stdout. Requests use `schemaVersion: 1`, `operation: pack|character`, bounded base64 files (`name`, `data`), and, for characters, an explicit immutable set of private content files supplementing the bundled pack. Empty private file lists are valid. The application supplies these files only after checking ownership. Worker inputs never include server paths or executable commands. Errors return `ok: false` and structured diagnostics; no preview or sheet is created on fatal input.

A successful character result contains `schemaVersion`, parser/version provenance, source SHA-256, content snapshot SHA-256, identity, six final abilities, final saves/skills/passives, AC, initiative, movement in feet, maximum/current/temporary HP, hit dice, final attacks, inventory, currency, spells/preparation, independent spellcasting/Pact Magic resources, features and notes. Every total carries its source/calculation provenance. Original build selections, final snapshot totals, and current play state remain separate. Missing play state is `null`; commit explicitly initializes HP/resources to full and temporary HP to zero only after the preview acknowledgement.

Diagnostic fields are `severity: error|warning`, stable `code`, `field`, and plain-text `message`. Required name, level, six abilities, HP and AC must resolve before commit. Missing selected content, duplicate IDs, unsupported numeric/conditional rules, cycles, invalid numbers, ambiguous shared slots, malformed XML and limit violations are fatal. Descriptions, attacks without supported automation, unknown prep state and absent play state can be retained with warnings. No unresolved numeric reference is silently replaced with zero.

Native target mapping uses fresh IDs and owner-only permissions. It inserts no default ruleset or subscribed-library effects. Abilities, AC, initiative, movement and proficiency become fixed native attributes. Saves/skills use fixed base values with no ability/proficiency added a second time. HP, hit dice and slots use native damage/reset counters; Pact Magic resets separately. Spells retain prepared/known/always-prepared flags and fixed casting totals. Descriptive content is escaped and remains manual. An import note preserves hashes, versions, warnings and the snapshot limitation after reload/archive. Changes to equipment, level or ability scores require manual review of the other snapshot totals.

Preview responses contain an opaque owner-bound ID, expiry, source/content hashes, normalized character, diagnostics, and `canCommit`. Preview inserts no creature data. Commit requires `previewId`, an opaque commit key and acknowledgement of all warnings. Server-side compare-and-set claims the preview; the resulting creature ID is stable across retries. A compensating rollback removes all inserted creature/property/experience records on failure. Staged characters remain hidden until commit succeeds. Cancellation applies only before commit; disconnect does not silently repeat work.

Limits: character 2 MiB; pack compressed 4 MiB; total expanded content 8 MiB; 100 XML files; 30,000 XML nodes per file; depth 64; 64 attributes per node; strings 20,000 characters; 5,000 content elements; 1,000 mapped properties; worker 15 seconds wall / 8 seconds CPU / 256 MiB address space; one active worker per user, two globally. ZIP accepts regular XML files only; no links, traversal, encrypted entries or remote indexes. DTDs, entities, XInclude and XML processing instructions are rejected. Nothing follows URLs or portrait paths.

The built-in pack is immutable, versioned, shared and available without upload. Its ID, version, licence and SHA-256 are included in every content result and snapshot fingerprint. Uploaded conflicting built-in IDs are rejected; exact structural duplicates are deduplicated. Uploaded append/remove patches are explicitly rejected until patch semantics are implemented. Private packs are immutable, versioned and owner-private. Identical source/snapshot/version yields the same normalized result. Preview/job temporary files expire after one hour. Committed source originals are private and retained until the user deletes the import source/history or account. Removing a source/pack never changes already imported snapshot values or their embedded hashes. Persistent originals/manifests reside in server-only Mongo collections and are included in the existing consistent database backups. Import sources have a separate 20 MiB per-user quota, with at most five saved private packs and three pending previews; they do not alter native image/archive storage accounting. Account deletion is followed by cleanup within one minute.

Mock states: `parsing`, `preview` (`canCommit`, `warnings`, `expiresAt`), `committing`, `complete` (`creatureId`), `failed` (`diagnostics`), and `cancelled`. UI must handle expired, unauthorized, busy, unavailable, quota and fatal-content responses. A disabled feature leaves native character/import flows available. All links are relative to the configured application prefix.

Fixtures are invented and CC0. Expected values are recorded independently of Flare output. Martial: level 3, STR 16, DEX/CON 14; HP 10+6+6+3×2=28, AC 14+2 shield=16, Athletics 3+2=5. Prepared caster: level 5, INT 18/CON 14; HP 6+4×4+5×2=32, DC 8+3+4=15. Multiclass: 3d6/2d8 with rolls 6,4,4,5,5 and CON +1 gives HP 29; ordinary 4/2 slots and two independent first-level Pact slots. Equipment: level 4, CON 16; HP 10+3×6+4×3=40, AC 15+2 DEX+2 shield+1 charm=20; explicit STR-set 21 gives modifier +5 and expertise Athletics +9. Unknown/missing content and malformed input must fail rather than manufacture totals.

Parser 1.0.1 reads the native `build/equipment`, `build/magic` and `build/input/attacks` locations, falling back to legacy top-level equivalents only when the native section is absent. Both locations present are fatal `AMBIGUOUS_SECTION`; data is never silently combined or dropped. Only text at the exact `character/display-properties/portrait/base64` leaf is omitted from the XML tree, producing `PORTRAIT_NOT_IMPORTED`. It is never decoded, fetched or rendered, and the original source/hash is preserved. Empty portrait placeholders do not warn. The normal 20,000-character limit remains on other XML text and attributes; text-limit diagnostics include the element path and threshold. Raw upload, structural and unsafe-XML limits still apply to the complete file, including portrait data.

Native `ID_LEVEL_1` through the validated saved level, with type `Level`, and the five known base-calculation `Grants` markers are handled by explicit snapshot calculations and listed in `provenance.nativeMarkers`. They are not compendium stubs. Imported pack definitions cannot replace these markers; mismatched types or levels are fatal. Unknown internal IDs remain subject to normal required-content errors. Aurora's saved HP rolls can include a pre-generated queue for future levels: require enough valid rolls for the current class level, at most 20 entries, and count only the first current-level entries. Unused future rolls never grant HP or advance a character.
